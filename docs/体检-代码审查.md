## 二、P0（会直接出事）与处置

### 1. 自动交卷在成功路径上永远不触发 ✅已修

`api/browser_exam.py` 的 `run_pass`：

```python
if not undone:
    stats["left"] = 0
    return stats      # ← 直接返回，跳过底部的交卷分支
```

第 0 轮做完就 `return`，底部「补足最少用时 → 停顿 → 交卷」永远到不了。
**修法**：改成 `break`，落到函数底部做收尾判定。
**后续决定**：借这次修复直接取消自动交卷——交卷不可逆，程序只负责把题答完并提示
「可以交了」。`submit_paper()` 与相关 JS 已整段删除，`run_exam` 的 HTTP 路径也不再调用
`final_submit()`，测试改成断言「任何情况下都不许交卷」。

### 2. 多选回读只判「非空」→ 少选被当成成功 ✅已修

```python
cur = wait_js(...) or ''
if cur:            # ← 点了 A、B 只写进 A 也算成功
```

**修法**：新增 `_picked_ok()`，按字母集合比对；判断题（true/false）仍按非空判；
若平台把答案写成认不出的格式，退回「非空即成功」，不因校验把已写入的答案判死。

### 3. 模型只回一半选项，被当成高置信答案 ✅已修

`ask_scored` 只检查 `if not items`。模型回 `{"items":[{"k":"A","v":0.9}]}`（漏 B/C）时，
单选取 A、置信度 0.9 ≥ 门槛 → 不复核；多选直接少选。
**修法**：检测缺失选项 → 置信度压到 0，强制走复核；同时 `score_to_keys` 单选加 0.45 绝对下限（全项低分不许「矮子里拔将军」）。

### 4. 连点两次「登录学习通」会永久丢掉原会话 ✅已修

第二次 `_backup_login_state()` 时 `cookies.txt` 已被第一次挪走，返回空字典并覆盖全局备份；
之后登录失败，原 cookie 再也回不来。
**修法**：`_login_lock` 保护「检查 + 备份」的原子性；启动/点登录时 `_rescue_login_backup()` 把残留 `.bak` 搬回。

### 5. `/api/start` 的「检查 + Popen」不是原子的 → 双击起两个刷课进程 ✅已修

`_lock` 在检查后立刻释放，Popen 在几十行之后（中间还有最长 60 秒的账号核对），
前端 `await post()` 期间按钮没禁用。
**修法**：加 `starting` 占位并拆成 `api_start`（加锁）→ `_start_task_locked`（原逻辑），`finally` 复位。

### 6. Flask 请求线程裸等 `form.Invoke` ✅已修

`sync_cookies` / `load_url` 在请求线程里同步阻塞等 WinForms UI 线程；UI 一忙，
`/api/exam/browser`、`/close`、`/login/open` 全部挂死，werkzeug 工作线程被逐个吃掉，
最后连 `/api/status` 都不回。
**修法**：三处全部套 `_run_with_deadline(..., 8~15s)`，超时返回 504 + 人话。

### 7. `cookies.txt` 先写盘再校验 ✅已修

第一次登录（没有 `.bak`）校验失败时，无效 cookie 留在盘上；下次打开考场会把它推进 WebView2，
**把用户刚在窗口里登录好的会话踢下线**。
**修法**：先写 `cookies.txt.tmp`，`_probe_login` 通过后 `os.replace` 生效；失败删临时文件。

### 8. `exam_embed` 从未导入（NameError 被 `except` 吞掉）✅已修

`api_login_open` / `api_login_collect` 三处写 `exam_embed.get(...)`，但 server.py 没有这个导入。
每次都抛 NameError → 被 `except Exception` 吞 → 登录窗口一直弹成独立窗口。
**修法**：新增 `_exam_stage()` 统一获取，失败写日志，不再静默。

## 七、残余风险（必须说清）

1. **以上全部是静态审查 + 离线单测的结论**。答题链路（点选、翻页、交卷）在这台机器上没有任何自动化覆盖，`browser_exam.py` 780 行是零测试。
2. 新增的 `_picked_ok` 依赖「平台把答案写成选项字母」这个假设。若真实平台写的是别的格式，会走「认不出 → 非空即成功」的兜底，不会比改之前更差，但也不会更好。
3. 自动交卷现在真的会触发了（之前是永不触发）。**这是行为变化，第一次跑建议盯完整场**，确认「补足最少用时 → 停顿 → 交卷」这条链在真实页面上走得通。
4. 建议接下来补一个「考场 DOM 录屏回放」测试：把一次真实考试的页面快照存成 HTML，用无头浏览器跑 `run_pass`，这样不依赖账号也能回归交卷链路。
