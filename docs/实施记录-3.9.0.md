## 一、已落地

### 1. 匹配层 `api/matcher.py`（新增）

把「答案文本 → 该点哪几个选项」抽成纯函数，移植了 ocsjs 的 resolver 思路：

| 能力 | 说明 |
|---|---|
| 归一化 | 全角转半角、异体字（⻛→风）、去标点空白、转小写 |
| 单向包含 | 只认「答案包含选项」，修 `TCP` 误选 `TCP/IP协议` |
| 相似度 | `SequenceMatcher`，阈值 0.60，只在精确匹配失败后用 |
| 符号消歧 | `-x` 与 `x`、`-2` 与 `2` 归一化后并列时，用保留符号的比较再筛 |
| 多片段合并 | `听党指挥#能打胜仗#作风优良` 合并后整体匹配 |
| 判断题词表 | 先长词后短词，「不正确」不会被「正确」抢走 |
| 选项级聚合 | `score_to_keys()`：单选看领先度，多选看阈值 + 落选项边界 |

`api/browser_exam.pick_keys()` 现在只做字段适配，匹配全部交给它。

### 2. 答题主链路：单答 + 选项级打分（`api/exam.py`）

- `labeled_options()`：把选项按展示顺序编号成 A/B/C，**不再依赖平台给的真实 key**
  （单选是 A/B/C、判断是 true/false），从根上消掉字母错位。
- `ask_scored()`：一次调用，返回每项 0~1 的把握 + 整题把握 `c`。
- `answer_objective()`：先单答；只有 **没选出 / 有歧义 / 把握 < gate** 才补第二次，
  且第二次换「先假定都错、逐一找错」的复核提示，不是原样复读。
- 批量统计：`exam_stats()` 累计调用次数与 prompt/completion token，
  作答结束后写进日志（`本次考试模型调用 N 次，约 X tokens`）。

**默认调用次数**：从「2~3 次/题，最坏 6 次」降到「1 次为主，约 2 成题 2 次」。

### 3. 登录链路事务化（`webui/server.py`）

- 打开登录页前把 `cookies.txt` / `login.json` 挪成 `.bak`；
- 任何一步失败（读不到 cookie、没有 `_uid`、校验超时、校验不通过）
  都会自动把备份搬回去，并在错误信息里注明「你原来的登录态已恢复」；
- 全部通过才删备份。

### 4. 考场开窗的静默失败（`webui/server.py`）

`sync_cookies()` 返回 0（本地有登录态却一条都没推进 WebView2）时**不再导航**，
直接返回 502 和一句可操作的话，而不是让用户落在登录页上干等。

### 5. 界面细节

- 考场「开始 / 重考」按钮不再卡在「打开中…」，成功和失败都会复位；
- 设置页新增「复核门槛」(`exam_conf_gate`)，默认 0.78，0.5–0.95 可调；
- `config_template.ini` 增加该配置项与注释。

### 6. 打包

`超星AI答题.spec` 的 `hiddenimports` 补了 `api.browser_exam`、`api.matcher`。
（3.8.4 那次「模块没打进包，子进程静默退出」的教训。）

## 四、上线前建议

1. 先在源码模式跑一场**可以放弃的考试**，看日志末尾那行 token 统计与真实卷面对不对得上；
2. 重点看三种题：多选（边界）、判断题（否定表述）、选项带公式的（符号消歧）；
3. 如果发现「该复核的没复核」（错题集中在低把握题），把「复核门槛」从 0.78 调到 0.85 再看一轮；
4. 对比一下旧版：同一门课，记录「调用次数 / 用时 / 答对题数」，用数据决定门槛值。
